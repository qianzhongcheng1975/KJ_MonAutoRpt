# KJ_MonAutoRpt 开发启动结论与阻塞项

## 结论（是否可以开始开发）
**可以开始开发。**

当前文档已经具备：
- 需求范围与流程定义
- 里程碑和优先级
- 技术落地草案（前后端与函数分工）

但为降低返工风险，建议按“可并行 + 有门禁”的方式启动：
- 前端先开工 Auth/路由/上传页壳子
- 后端先开工 Firestore 规则、Functions 骨架、数据类型定义
- 在 Sprint 1 末设置一次“门禁评审”再进入自动分析与邮件模块

## 启动前必须补齐（Blocking Checklist）
以下项目建议在 **1~2 天内**确认，否则会影响后续迭代效率：

1. **环境与项目归属**
   - Firebase Project ID（dev/staging/prod）
   - Cloud Functions 区域（如 `asia-east1`）
   - 默认时区（建议 `Asia/Shanghai`）

2. **邮件供应商与域名能力**
   - 二选一：SendGrid / Resend
   - 发件域名 DNS、SPF、DKIM 是否已可配置
   - 失败告警接收邮箱

3. **OCR/ASR 策略边界**
   - MVP 是否支持图片 OCR 与会议 ASR 全量
   - 若暂不支持，明确降级策略（仅文本类先上线）

4. **关键字段最终命名冻结**
   - `month` / `reportMonth` / `report_month` 三者统一
   - `status` 枚举值冻结（draft/generated/sent/failed）

5. **数据合规与留存策略**
   - 上传文件保留时长
   - 报告与审计日志保留时长

## Sprint 1 开工清单（建议直接建任务）

## A. 平台与工程化
- 初始化 Firebase（Auth/Firestore/Storage/Functions）
- 建立 `.env.example` 与环境变量命名规范
- 建立 TypeScript lint/format（frontend + functions）

## B. 前端（并行）
- 登录页与鉴权守卫
- 基础路由与布局（uploads/summaries/reports/settings）
- 上传页表单（标签必填校验先本地完成）

## C. 后端（并行）
- Firestore/Storage 规则初版
- `functions/src/index.ts` 与 trigger 文件骨架
- 统一类型：User/Upload/Summary/Report/Job

## D. 验收门禁（Sprint 1 结束）
- member 与 admin 权限边界可验证
- 上传流程“文件+标签+文档写入”可跑通
- CI 至少跑通 lint + typecheck

## 开发启动建议（执行顺序）
1. 先做“无争议基础设施”（鉴权、路由、规则骨架、类型）
2. 再做“可验证闭环最短路径”（上传 -> uploads 文档）
3. 最后接入“高不确定模块”（自动分析、OCR/ASR、邮件）

## 风险提示（当前最可能卡点）
- 邮件供应商配置与域名验证经常阻塞联调。
- OCR/ASR 质量会影响 summaries 体验，必须预留人工编辑入口。
- 触发器并发会导致重复写，需尽早实现幂等键。
