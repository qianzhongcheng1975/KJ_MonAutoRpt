# KJ_MonAutoRpt 技术落地草案

## 1. Firestore Security Rules 草案（最小权限）

> 目标：用户仅访问自身数据；关键系统字段仅服务端函数更新。

```rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isSignedIn() { return request.auth != null; }
    function isOwner(uid) { return isSignedIn() && request.auth.uid == uid; }
    function isAdmin() {
      return isSignedIn()
        && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }

    match /users/{uid} {
      allow read: if isOwner(uid) || isAdmin();
      allow create: if isOwner(uid);
      allow update: if isOwner(uid) || isAdmin();
      allow delete: if isAdmin();
    }

    match /uploads/{uploadId} {
      allow read, create: if isOwner(request.resource.data.uid);
      allow update, delete: if isOwner(resource.data.uid);
    }

    match /summaries/{summaryId} {
      allow read: if isOwner(resource.data.uid) || isAdmin();
      allow create: if isOwner(request.resource.data.uid);
      allow update: if isOwner(resource.data.uid)
        && !('createdBy' in request.resource.data)
        && !('sourceUploadIds' in request.resource.data); // 可按需求放宽
      allow delete: if isOwner(resource.data.uid) || isAdmin();
    }

    match /reports/{reportId} {
      allow read: if isOwner(resource.data.uid) || isAdmin();
      allow create: if isOwner(request.resource.data.uid);
      allow update: if isOwner(resource.data.uid)
        && request.resource.data.status == resource.data.status
        && request.resource.data.sentAt == resource.data.sentAt;
      allow delete: if isOwner(resource.data.uid) || isAdmin();
    }

    match /settings/{docId} {
      allow read: if isSignedIn();
      allow write: if isAdmin();
    }

    match /jobs/{jobId} {
      allow read: if isAdmin();
      allow write: if false; // 仅函数服务账号写
    }
  }
}
```

## 2. Cloud Functions 目录与函数清单

```text
functions/
  src/
    index.ts
    triggers/
      uploads.ts         # onUploadCreated
      summaries.ts       # onSummaryChanged

    services/
      parser.ts          # 文本提取/OCR/ASR
      summarizer.ts      # 二级字段概要生成
      report-builder.ts  # 报告组装、PDF 生成
      mailer.ts          # SendGrid/Resend 适配
      retry.ts           # 重试与退避策略
    repositories/
      uploads.repo.ts
      summaries.repo.ts
      reports.repo.ts
      jobs.repo.ts
      settings.repo.ts
    shared/
      constants.ts       # module/field 映射、状态常量
      types.ts
      logger.ts
```

### 2.1 触发器职责
- `onUploadCreated`
  - 校验标签
  - 提取文本
  - 调用 summarizer 生成/更新 summaries
  - 记录 job 状态
- `onSummaryChanged`
  - 当月 summaries 变化触发报告重建（可做防抖）
- `onReportGenerated`
  - 读 settings，触发邮件发送
  - 失败按 retry policy 排队重试
- `onDailyCheck`
  - 扫描未发送报告，触发补偿投递
- `onMonthEndSchedule`
  - 每月最后一天 18:00 强制 generate + send

## 3. 前端页面与接口（建议）

## 3.1 页面结构
- `/login` 登录页
- `/uploads` 上传页
- `/summaries` 概要管理
- `/reports/:month` 报告预览与编辑
- `/settings` 管理页（admin）

## 3.2 前端状态分层
- `authStore`：用户身份与角色
- `uploadStore`：上传队列、标签表单、进度
- `summaryStore`：按 month 拉取 + 编辑缓存
- `reportStore`：报告详情、状态、发送历史
- `settingsStore`：分类配置、收件人配置

## 3.3 API/Hook 约定
- `useMyProfile()`
- `useUploads(month)` / `createUploadMeta(payload)`
- `useSummaries(month)` / `updateSummary(id, content)` / `regenerateSummary(id)`
- `useReport(month)` / `saveReportDraft(report)` / `triggerSend(reportId)`
- `useGlobalSettings()` / `saveGlobalSettings(data)`（admin only）

## 4. 关键实现细节
- **幂等键**：`uid:month:moduleKey:fieldKey`，防重复写。
- **摘要裁剪**：统一 `trimTo100Chars()`，服务端最终兜底。
- **状态机**：`draft -> generated -> sent|failed`，仅 Functions 推进。
- **可追踪性**：每次函数执行绑定 `jobId` 与 `correlationId`。
